# Dashboard CSS Completion Design

## Goal

Bring the MYBOT operations dashboard to a finished, consistent UI state by
consolidating its stylesheet and improving desktop and mobile ergonomics without
changing the dashboard APIs, routes, or operational behavior.

## Scope

The work is CSS-first and covers the complete dashboard shell, existing page
components, the Overview workspace, and their shared interaction states. It
does not add a design framework, change the existing HTML structure except for
accessibility-critical hooks discovered during verification, or alter backend
code.

## Visual Direction

The dashboard remains a dark operations interface. The page uses near-black
surfaces with cyan as the primary action and focus color, green for healthy
states, amber for warnings, and coral for destructive/error states. Decorative
effects are deliberately restrained: no large gradients or floating effects;
the interface earns hierarchy through contrast, spacing, typography, borders,
and status color.

## CSS Architecture

`dashboard/public/css/style.css` becomes a single ordered visual system:

1. Reset, typography, and one semantic token block.
2. Application shell: sidebar, topbar, content container, and page transitions.
3. Shared components: buttons, icon buttons, form controls, cards, tables,
   status badges, empty states, modal, drawer, toast, and loading/error states.
4. Workspace-specific Overview rules.
5. Responsive and reduced-motion overrides.

Earlier repeated variable blocks and competing component definitions are
removed. Existing class names and IDs remain the integration contract.

## Desktop Experience

At 1280px and above, the sidebar remains fixed and readable, the topbar keeps
the search and operational controls grouped, and content uses a bounded
1520px-wide reading area. Cards use a 7px radius, a quiet one-pixel border, and
a small elevation only when needed. Dense tables retain sticky headers and
horizontal scrolling within their own container.

The Overview workspace is structured as a compact control bar, labelled metric
tiles, health indicators, a fixed-height chart region, fleet table, and activity
stream. Its KPIs must be distinguishable without relying only on color.

## Mobile Experience

At 760px and below, the sidebar becomes a focused drawer with a visible
backdrop. The topbar preserves navigation and high-priority operational buttons
while removing nonessential search and fullscreen controls. Cards, forms, and
Overview grids stack without horizontal page overflow; wide tables scroll only
inside their table container. Toasts are positioned above the safe screen edge
and cannot overlap the bottom of a modal/drawer.

## Interaction and Accessibility

All interactive controls receive visible keyboard focus, hover and pressed
states where relevant, and clear disabled styling. Async surfaces support
loading, empty, stale, and retryable error states. The modal, confirmation
overlay, command palette, bot drawer, and toast container layer predictably.
`prefers-reduced-motion` disables nonessential animation.

## Verification

Run the full Node test suite and the UTF-8 checker. Start the existing dashboard
server, capture screenshots at 1440x900 and 390x844, and inspect that the page
is nonblank, no primary content overlaps, tables remain contained, the mobile
drawer width follows `min(82vw, 300px)`, and visible text fits its controls.

## Constraints

- Preserve current dashboard routes, IDs, class names, API contracts, and
  JavaScript behavior.
- Use the loaded Space Grotesk and JetBrains Mono assets; do not add a
  dependency.
- Use ASCII only in CSS and documentation generated by this change.
- Keep UI surfaces at 8px radius or less.
